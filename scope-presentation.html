🧩 Modular Programming

Small functions with one clear job

Why it is usually better than one big function

Two Styles

Monolithic style

One large function does everything end-to-end.

Modular style

Many small functions each do one thing.

Modular style follows the Single Responsibility Principle.

Why Big Functions Become Painful

  • Harder to read and understand quickly
  • Harder to test because everything is coupled together
  • Harder to debug because many concerns mix in one place
  • Harder to reuse only one piece of logic
  • Riskier to change without breaking unrelated behavior

Benefits of Modular Programming

  • Readability: each function is easier to scan
  • Testability: unit-test each small function
  • Reusability: reuse helpers in multiple places
  • Maintainability: change one part safely
  • Collaboration: teammates can work in parallel

Example: One Big Function

function checkout(cart, user, couponCode) { let subtotal = 0; for (const item of cart) { subtotal += item.price * item.qty; } let discount = 0; if (couponCode === "SAVE10") discount = subtotal * 0.1; const taxed = (subtotal - discount) * 1.2; const shipping = taxed > 100 ? 0 : 8; const total = taxed + shipping; return { userId: user.id, subtotal, discount, shipping, total }; }

Same Logic, Modular Version

function calculateSubtotal(cart) { return cart.reduce((sum, item) => sum + item.price * item.qty, 0); } function calculateDiscount(subtotal, couponCode) { return couponCode === "SAVE10" ? subtotal * 0.1 : 0; } function calculateShipping(amountAfterTax) { return amountAfterTax > 100 ? 0 : 8; } function checkout(cart, user, couponCode) { const subtotal = calculateSubtotal(cart); const discount = calculateDiscount(subtotal, couponCode); const amountAfterTax = (subtotal - discount) * 1.2; const shipping = calculateShipping(amountAfterTax); const total = amountAfterTax + shipping; return { userId: user.id, subtotal, discount, shipping, total }; }

Testing Becomes Easier

// test calculateDiscount in isolation expect(calculateDiscount(200, "SAVE10")).toBe(20); expect(calculateDiscount(200, "NONE")).toBe(0); // test shipping rules separately expect(calculateShipping(120)).toBe(0); expect(calculateShipping(80)).toBe(8);
Small functions = focused, fast unit tests ✅

When to Keep It Simple

Modular does not mean splitting everything into tiny fragments.

  • If logic is truly simple, one short function is fine
  • Split when responsibilities start mixing
  • A good rule: each function should have one clear reason to change

Key Takeaway 🎓

The style you asked about is commonly called modular programming (or functional decomposition).

Compared to one big function, it usually gives cleaner code, better tests, safer changes, and easier teamwork.
